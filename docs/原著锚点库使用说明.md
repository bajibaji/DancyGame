# 原著锚点库使用说明

这份库把《空相沙漏》（初禾二）全书 139 章整理成可查的事实账，覆盖凶喜、山灼、粉梅、沙漏与终章，给游戏写稿做对照。每条事实都带原文章号和行号，能回到原书核对；游戏里的人和线索都注明了对应关系，改名、同名异义、游戏原创另行标出。

原著全文就在本项目 `book/parts/` 的十个分卷里，章节边界见 `book/chapters_index.json`。库里的行号沿用整本原稿编号，跟索引一致，跟分卷文件内的行号不同；核对原文时按章号找到分卷，再按正文定位。

## 查什么

在仓库根目录运行：

```powershell
node scripts/canon.mjs 总览
node scripts/canon.mjs 人物 海姝
node scripts/canon.mjs 人物 江嘉
node scripts/canon.mjs 线索 C04
node scripts/canon.mjs 章节 21
node scripts/canon.mjs 差异
```

- 总览：当前覆盖范围与各类事实数量。
- 人物：查游戏人物对应原著谁、身份是否吻合、原著首次出场在哪一章。
- 线索：查游戏线索的原著事实出处、章号行号、当时谁知道。
- 章节：按原文章号列出该章的事件与证据，插叙会单独标出。
- 差异：写稿最容易踩的改名、同名异义与游戏原创设定。

## 写稿怎么用

准备写一个单元之前，先按出场人物、要用到的线索各查一次，再看差异清单。原著事实可以作为动机、时间点和证据先后的依据；差异清单里标为「游戏原创」的内容不要回填到原著事实里。遇到同名人物，先看差异清单再动笔，卢旭和袁衷在原著与游戏里是两回事。

## 给大模型用

`book/AGENT.md` 是给大模型读的入口：查库命令、四条红线和数据边界都写在那里。新模型接手时把这一个文件交给它即可，不用每次重新交代；人看的使用说明仍是本文件。

## 校验

`npm run check` 已经包含锚点库检查：编号不重复、行号落在标注章节内、章号与行号一致、知悉章号与行号一致、人物与线索引用有效、没有同一事实重复记账、线索链接双向一致、映射目标存在、已开放章节用到的每条线索都有原著出处。状态只有四种，每种都有严格判定：人物标成游戏原创却填了原著对应，或名字在原著全书出现过，都会直接报错；线索标成游戏原创却填了原著锚点同样报错。改动游戏线索或锚点库后，跑一次总检查即可。

## 边界

- 全书 139 章已入库，但抽取按单元分段、每段有条数上限；查不到的事实不等于没有，仍要回原文核对。
- 映射只有四种状态：确证是同名同位、可直接引用；改名对应是原著有依据、游戏改了名字或细节；同名异义是名字相同身份不同；游戏原创是原著全书查无对应。四种都已逐条对过原文，不再有「还没查」的灰色状态。
- 事实由 AI 逐段抽取后去重整理，关键情节和人物身份仍需回到原文人工复核；库里不保存原著原文长段。
- 全部事实的章号已按原文行号校正，并纳入自动校验；回原文核对仍建议按章号与正文定位，不要只按行号。
- 人物表里有少量「群体或泛称，非单一人物」占位条目，例如机构与泛称，不要当成具体人物引用。
- 事件按原文章号排列；标了插叙的事件在故事里发生得更早，发生顺序尚未逐条校正。
- 新增单元时按同一套字段续写，并同步更新 `book/meta.json` 的数量与范围。
